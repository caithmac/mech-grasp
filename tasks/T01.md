# T01 - Atom-level probes: does GRASP compute chemistry that is NOT in its input token?

Question: GRASP's input token for an atom is only (element, degree, H count, charge, mass, in-ring).
Does the model build context-dependent chemical properties, layer by layer?

Use data.get_acts("atoms","pretrained"), data.get_acts("atoms","random"), data.get_atom_labels("atoms"),
data.get_scaffolds("atoms"), and probes.probe_atoms with layers=list(range(13)) for these columns:
  aromatic, hybridization, conjugated, min_ring_size, has_O_neighbor, has_N_neighbor,
  has_halogen_neighbor, fg_carbonyl_C, fg_amide, fg_ester, fg_carboxylic_acid, fg_nitrile,
  fg_aromatic_N, fg_michael_acceptor
and as sanity (in-token, should be ~perfect from the token baseline): tok_element, tok_in_ring.

ALSO run the 'aromatic' and 'hybridization' probes restricted to carbon atoms in rings
(mask = (df.tok_element=="C") & (df.tok_in_ring==1)) - this is the hard case where the token cannot
tell benzene from cyclohexene.

results.json: {"<column>": probe result dict, ..., "aromatic_ring_C": ..., "hybridization_ring_C": ...,
 "summary": {"<column>": {"token": mean, "best_layer": l, "grasp_best": mean, "random_at_best": mean,
 "gap_vs_token": x, "gap_vs_random": y}}}
Figure: one subplot per column, x = layer, lines = grasp, random, token baseline (flat), with std bands.
