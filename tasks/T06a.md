# T06a - SMILES atom-order sensitivity by layer

Fact (supervisor-verified): GRASP has absolute position embeddings, so the order atoms appear in the
SMILES string affects the embedding.

Steps (keep the script short):
1. smi = data.get_smiles("atoms")[:300]. For each, make 5 random orderings:
   Chem.MolToSmiles(Chem.MolFromSmiles(s), doRandom=True, canonical=False).
   Build flat lists: variants (1500 strings) and parent (1500 ints, the index of the source molecule).
2. For model in ["pretrained", "random"]: enc = model.load(kind);
   base = model.run(enc, smi); var = model.run(enc, variants)    # ONE call each
   For each layer l in 0..12: d_cls = utils.cosine_distance(base.cls[l][parent], var.cls[l]);
   d_mean = utils.cosine_distance(base.mean[l][parent], var.mean[l]). Store mean, median, max.
3. Retrieval (pretrained only), layers [3, 6, 9, 12]: E = data.get_acts("atoms","pretrained").cls[l]
   (4000 canonical molecules; molecule i of smi is row i of E). S = utils.pairwise_cosine on
   np.vstack([var.cls[l], E]), take rows 0..1499 and columns 1500..; hit = S.argmax(1) == parent.
   Report hit.mean().
results.json: {"per_layer": {kind: {"cls": {l: {...}}, "mean": {l: {...}}}}, "retrieval": {l: rate}}
Figure order_by_layer.png: x=layer, y=mean distance, 4 lines (pretrained/random x cls/mean).
