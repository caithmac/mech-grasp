# T16a - GRASP-A3 is GIVEN aromaticity, ring membership and hybridization. What does it still have to compute?

GRASP-A3 = GRASP-A2 (bond-type + stereo inputs, no absolute positions) but the opaque atom token is replaced by
7 categorical atom fields: element, degree, total H, formal charge, aromatic, in-ring, hybridization.
So for A3, aromaticity / ring membership / hybridization are INPUTS. Ring SIZE, conjugation, Crippen contributions
and neighbour / functional-group context are still NOT inputs and must be computed from the graph.
Controls: "a3_random" (A3 architecture, random weights, SAME 7 fields + bond/stereo inputs) and, for comparison,
("a2", "a2_random"). Anything the random control decodes comes from the inputs, not from learning.

IMPORTANT - the input baseline. For a FAIR comparison of A3 and A2 use the SAME input ids for both pairs:
  bundle = data.get_atom_fields("atoms")["bundle"].values      # 7-field bundle per atom (finer than the hashed token)
  and pass tokens=bundle to EVERY probes.probe_atoms call (both pairs). Its "token" result is then the bundle baseline.

Setup: smi = data.get_smiles("atoms"); scaf = data.get_scaffolds("atoms"); df = data.get_atom_labels("atoms").
Pairs (first = model, second = its random control; probe result keys are always "grasp" and "random"):
  ("a3", "a3_random") and ("a2", "a2_random"); acts = data.get_acts("atoms", kind). Layers [0, 2, 4, 6, 8, 10, 12].
Concepts (probes.probe_atoms(y, M, Rnd, scaf, layers=LAYERS, tokens=bundle, ...)):
  ring_size       : df.min_ring_size as int, mask = df.min_ring_size > 0 (multi-class -> balanced accuracy)
  conjugated      : df.conjugated, ambiguous_only=True
  crippen         : df.crippen_logp_contrib (regression R2)
  mr              : df.crippen_mr_contrib (regression R2)
  o_neighbor_C    : df.has_O_neighbor, mask = (df.tok_element == "C")
  halogen_nbr_C   : df.has_halogen_neighbor, mask = (df.tok_element == "C")
  hydroxyl_C      : df.fg_hydroxyl, mask = (df.tok_element == "C")   (skip if < 30 positives under the mask)
Input sanity (do NOT probe): report, for A3, whether df.aromatic and df.hybridization are a function of the bundle:
  is_input[c] = all(df.groupby(bundle)[c].nunique() == 1).
Wrap each probe_atoms call in utils.memo(f"t16a_{pair}_{concept}_v1", ...).
For every concept, pair and layer report model mean/std, control mean/std, bundle baseline, and ERROR (1 - score).
Derived per concept and pair: best layer, best model error, control error at that layer,
learned_gain = control_error / model_error at the best layer.
results.json: {"is_input": {...}, concept: {"a3": {"layers": {L: {"model", "model_std", "control", "control_std"}},
               "bundle_baseline", "best_layer", "best_err", "control_err_at_best", "learned_gain"}, "a2": {...same}}}
Figure t16a.png: one panel per concept, error vs layer (log y): a3 solid, a3_random dashed, a2 solid, a2_random dashed.
Reference (T15a, token baseline, not bundle): ring_size best error A1 0.185, A2 0.245.
Questions: with aromaticity/ring/hybridization handed to it, is A3 better or worse than A2 on the concepts it must still
compute? Is its learned_gain over its own random control larger or smaller than A2's? Does a3_random already solve
some concepts that a2_random cannot (i.e. are they now nearly given by the richer inputs)?
